# API регистров v1

Все адреса нулевые, без обозначений 4xxxx/3xxxx. FC03 читает holding,
FC04 читает input, FC06/16 пишет holding. Команды доступны только на запись.
float32 и uint32 занимают два регистра, старшее слово первым; байты каждого
регистра передаёт Modbus в стандартном порядке. Длины — метры, углы — радианы.

## Holding

| Адрес | Размер | Содержимое |
|---|---:|---|
| 0x0000 | 1 | Команда: 1 BEGIN, 2 APPLY, 3 SUBMIT, 4 ACK |
| 0x0100 | 1 | Число вращательных суставов 3–6 |
| 0x0101 + 16*i | 12 | Шесть float: a, alpha, d_offset, theta_offset, min, max |
| 0x010D + 16*i | 4 | Резерв, игнорируется |
| 0x0161 | 32 | Матрица world_base 4x4, построчно |
| 0x0181 | 32 | Матрица last_tool 4x4, построчно |
| 0x0200 | 2 | ID запроса / ID подтверждаемого результата |
| 0x0202 | 6 | Цель TCP: x,y,z |
| 0x0208 | 12 | Шесть начальных углов (неиспользуемые передавать нулями) |

Запись модели разрешена только в состоянии настройки, не во время APPLY.
BEGIN обнуляет staging и маски заполнения, отменяет запросы/результаты старого
сеанса. Уже запущенный IK дорабатывает, его результат отбрасывается.
APPLY требует все используемые DH/limits и обе полные матрицы; единичные матрицы
тоже передаются явно. NaN/Inf, неверные границы и преобразования отклоняются.
APPLY только принимает команду: завершение нужно опрашивать в input.
После ошибки проверки worker остаётся в настройке, status содержит ошибку библиотеки.

SUBMIT требует все 20 слов, в том числе ID и шесть начальных углов. Входы
копируются в запрос: последующие записи не меняют ожидающий расчёт. После принятия
маска заполнения запроса очищается: повтор требует новой записи всех полей.
При отказе заполненные поля остаются, команду можно повторить.
ACK требует запись ID в 0x0200–0x0201 и совпадение с головой FIFO результатов.
Чтение не удаляет результаты. Клиент обеспечивает уникальные ID активных запросов.

Очередь вмещает 8 ожидающих запросов плюс один выполняющийся. Результаты — FIFO
на 8 элементов; при заполнении worker ждёт ACK и не извлекает следующий запрос.
BEGIN также очищает непрочитанные результаты — клиент должен учитывать смену сеанса.

## Input

| Адрес | Размер | Содержимое |
|---|---:|---|
| 0 | 1 | Версия протокола = 1 |
| 1 | 1 | Режим: 0 настройка, 1 применение, 2 runtime |
| 2 | 1 | Worker занят (в том числе завершает отменённую работу) |
| 3 | 1 | Ожидающие запросы |
| 4 | 1 | Непрочитанные результаты |
| 5 | 1 | Статус настройки k_status |
| 6 | 1 | Есть результат |
| 7 | 2 | ID головы результатов |
| 9 | 1 | Статус IK k_status |
| 10 | 12 | Шесть углов, результат действителен только при K_OK |
| 22 | 2 | Residual, диагностическое поле; при отсутствии значения = 0 |

FC04 берёт согласованный снимок под короткой блокировкой. Результат не меняется
до ACK или BEGIN; читайте все 24 регистра одним запросом. Углы за числом суставов
равны нулю. Нулевая residual сама по себе не доказывает успех: проверяйте status.

Исключения: 02 — неверный адрес; 03 — неверное значение/неполные поля/неверный ACK;
04 — устройство пока не готово или очередь полна. nanoMODBUS выбранного API
поддерживает исключения 01–04, поэтому busy отображается в 04, не 06.

SAVE/LOAD и параметры UART пока не входят в реализованный протокол.

## Подключение nanoMODBUS

Исходники нужны в `third-party/nanoMODBUS` либо задайте CMake NANOMODBUS_PATH.
Если их нет, host-тесты проверяют карту и приложение без RTU-парсера.
`Server` подключает callbacks FC03/04/06/16. Передайте ему transport=RTU,
read/write callbacks из будущего UART-адаптера и адрес 1–247. Один protocol task
вызывает poll(); установить конечные таймауты до первого poll.
Вызовы из ISR запрещены. Broadcast-команды выполняются без ответа по правилам
nanoMODBUS, поэтому клиенту следует использовать unicast для команд с подтверждением.
Тайминги кадров и реальный RTU CRC-трафик пока не проверены.

## UART и сохранение (расширение v1)

Holding 0x0300..0x0303: slave ID, baud uint32 (старшее слово первым), parity
(1=even/8E1, 0=none/8N2). Значения отложенные: действуют после SAVE и reset,
текущая линия не переключается посреди ответа. Baud 38400–115200, ID 1–247.

Команда 5 SAVE: только runtime, worker свободен, очереди запросов/результатов пусты.
Сохраняются текущая модель, настройки линии и константы решателя прошивки.
Команда 6 LOAD: только настройка, восстанавливает staging; затем требуется APPLY.
При запуске LOAD выполняется автоматически, без автоматического APPLY.
BEGIN очищает модель/входы, но сохраняет отложенные настройки линии.
При отсутствующей/повреждённой записи LOAD возвращает 04.
Физический UART-транспорт игнорирует broadcast (адрес 0), без побочных эффектов.
Эти уточнения заменяют прежние замечания о нереализованных SAVE/LOAD и broadcast.
