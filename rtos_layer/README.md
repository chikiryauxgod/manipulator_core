# rtos_layer

Небольшая header-only библиотека C++17 над native FreeRTOS API. Не зависит от
STM32 HAL или CMSIS-RTOS. Не выделяет память в heap, не использует исключения/RTTI.
Библиотека находится в основном репозитории, сохраняя отдельный CMake target;
при появлении собственного remote её можно выделить в отдельный репозиторий.

## Состав

- `StaticQueue<T, N>`: статическая очередь, только trivially copyable сообщения.
- `StaticMutex`: статический нерекурсивный mutex с наследованием приоритета FreeRTOS.
- `MutexGuard`: освобождает mutex только при успешном захвате; проверяйте `owns_lock()`.
- `Notification`: счётное уведомление задачи на индексе 0.

Задачи, их стеки, приоритеты, IRQ, FreeRTOSConfig.h и ядро предоставляет приложение.
Нужны configSUPPORT_STATIC_ALLOCATION=1, configUSE_MUTEXES=1,
configUSE_TASK_NOTIFICATIONS=1 и configASSERT. Потоки создаются отдельно.
Таймауты выражены в тиках; преобразование из миллисекунд выполняет вызывающий код.
Бесконечное ожидание portMAX_DELAY зависит от конфигурации FreeRTOS.

Объекты очередей и mutex нельзя копировать/перемещать. Они должны жить дольше
всех использующих их задач/ISR. Уничтожение допустимо только после прекращения
использования, без ожидающих задач. Не выполняйте блокирующие операции до запуска
планировщика. Mutex запрещён в ISR. Методы без суффикса `_from_isr` — для задач.

В ISR начните с `BaseType_t woken = pdFALSE`, передавайте одну переменную всем
операциям и в конце вызовите портовый `portYIELD_FROM_ISR(woken)`. ISR должен иметь
приоритет, разрешающий вызовы FreeRTOS API. Обёртки сами переключение не вызывают.
Уведомление index 0 нельзя одновременно использовать другим протоколом уведомлений
этой задачи. `Notification::take` читает уведомление текущей задачи.

## Подключение

В CubeIDE добавьте `include/` в include paths C++ и подключите ядро FreeRTOS.
В CMake используйте `add_subdirectory`, затем target `rtos_layer::rtos_layer`;
пути к FreeRTOS, его порту и конфигурации приложение добавляет отдельно.

```cpp
#include <rtos_layer/queue.hpp>
struct Request { unsigned id; float target[3]; };
// Создаётся до запуска задач и живёт до конца работы приложения.
static rtos_layer::StaticQueue<Request, 8> requests;
```

## Проверка на ПК

```
cmake -S . -B build -DRTOS_LAYER_BUILD_TESTS=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

Тестовая реализация API проверяет передачу данных, полную/пустую очередь,
таймауты, владение mutex и передачу ISR-флага. Она не моделирует планировщик,
приоритеты, реальные ожидания или аппаратные прерывания. Требуется интеграционная
проверка с настоящим FreeRTOS на целевом МК перед использованием в прошивке.

### Интеграция с настоящим ядром (Linux)

Проверено с FreeRTOS-Kernel V11.1.0 и его POSIX-портом:

```
cmake -S . -B build -DRTOS_LAYER_BUILD_TESTS=ON \
  -DRTOS_LAYER_FREERTOS_PATH=/absolute/path/to/FreeRTOS-Kernel
cmake --build build
ctest --test-dir build --output-on-failure
```

Тест запускает две статические задачи настоящего ядра и проверяет блокирующий
приём, передачу сообщения, уведомление, захват/освобождение mutex и таймаут.
POSIX-порт и тестовая конфигурация допускают heap для внутренних нужд симулятора;
это не конфигурация STM32. ISR-операции проверены только тестовой реализацией API.
На STM32 ещё нужны проверки приоритетов IRQ, переключения из ISR и стеков.
